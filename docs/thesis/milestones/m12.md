## Bugs

### Found

**BUG-034 — `str != str` always returns true.** Found by C9 (B-tree). The
B-tree's search test built `PASS got=X` / `FAIL got=X want=Y` output via a
string inequality compare; every line printed FAIL even when the searched
value matched. Bisect to `_probe_str_ne.spy` (4 println lines) confirmed:
`a != b` for two literally-equal strings returns `true`. Diagnosed to
`compiler/src/ir.rs::emit_binop`: the `AstBinOp::Ne` arm had no `is_str`
branch and fell through to `INe`, which compared the two heap-pointer u64s.

Identical structural shape to **BUG-008** (`is not` was emitting `RefEq`
not `not RefEq`). Both bugs are: "negative form of an equality test
missing the new-type branch in the lowerer." Both stayed latent because
every prior example happened to use the positive form for that operator.

Fixed inline in M12: lower `Ne` on str operands as `StrEq` followed by
`BoolNot`, mirroring the existing `IsNot` shape. 4-line patch.
Regression test: `compiler/tests/btree_runs.rs::str_ne_returns_false_for_equal_strings`.

**BUG-035 — `and` and `or` do not short-circuit.** Found by C9. The
B-tree's insertion sort uses `while b > 0 and ranks[b-1] > ranks[b]` —
the standard guarded-index idiom. The right operand evaluates
unconditionally, so the first iteration trips `IndexError: index -1 out
of range`. Diagnosed to `compiler/src/ir.rs::emit_binop` lines 1738-1739:
`And → IAnd`, `Or → IOr`. The source comment ("bitwise approximation")
documents the limitation honestly.

Deferred. Fix requires emitting new basic blocks mid-expression for
`a and b → if a: b else: false` — the first feature in the project that
needs IR branching for a single expression. Mechanically tractable but
out of M12's confirm-M11 scope.

## Lessons (new vs M11)

1. **Confirmation results are deliverables.** Pre-M11 every class-heavy
   program was a bug catalogue with a long workarounds section. The
   regex agent's report — "8 subclasses, 6 virtual methods, class-ref
   fields, no workarounds, 10/10 clean runs" — is itself the proof that
   M11 landed.

2. **Negative-form silent miscompiles hide behind positive-form
   conventions.** Both BUG-008 (`is not` inverted) and BUG-034
   (`str !=` always true) were latent for ~10 milestones because every
   example happened to write the positive form. The shape is:
   any new comparison operator that adds an `is_<type>` branch in
   `Eq` needs the matching branch in `Ne`. Mechanical lesson for the
   thesis methodology chapter: tests need both equality forms for any
   new operator.

3. **Torture tests are how provisional fixes become confirmed.** Cost:
   ~30 minutes of agent compute + ~5s of CI per run. Benefit:
   converting "5/5 sample" to "250/250 quantified evidence." That trade
   should be standard practice when a class-of-bugs gets a structural fix.
