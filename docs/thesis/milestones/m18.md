## The bug

**BUG-036**: `try: 1/0 except ZeroDivisionError as e: ...` did not
catch. Runtime emitted legacy `DivisionByZeroError`; arm-match was
exact-string; spec said `ZeroDivisionError` was canonical. R3's
expression interpreter deliberately probed both names (its evaluator
runs runtime errors caught at top level), and the probe surfaced the
drift.

Fix:
1. Four divzero emit sites in `vm/src/interp.rs` (lines 915, 947, 978,
   1008 — i32/i64/u32/u64 paths) changed to emit canonical
   `ZeroDivisionError`.
2. New `exception_name_alias` helper that maps legacy
   `DivisionByZeroError` → `ZeroDivisionError`, used by the
   arm-matcher in `propagate_exception`. Both names catch.

Regression: `vm/tests/m18_divzero_alias.rs` — 3 tests covering
canonical name catches, legacy name catches via alias, i32 path emits
canonical.

## The R2 LOC delta (workaround inventory)

M10's `json_parse.spy` documented 8 language workarounds in its header.
R2's `json_parse_v2.spy` writes the natural form with all 8 eliminated:

| M10 workaround | M10 form | M18 form |
|---|---|---|
| `sealed` dropped vdispatch | `open class JsonValue` | `sealed class JsonValue` |
| Subclass fields aliased | empty parent | `JsonNumber {n: f64}` works |
| Vtable wraps at 4 | 3 subclasses | 6 subclasses |
| str-arg methods corrupt heap | free fns `p_foo(p, s)` | Parser instance methods throughout |
| Declaration order affects crash | JsonObject FIRST | Natural Null → ... → Object order |
| Dict[K,V] only primitive V | parallel `List[str]` + `List[JsonValue]` | `List[Tuple[str, JsonValue]]` |
| No isinstance / no match | virtual `render()` everywhere | `match v: case JsonObject(pairs): ...` |
| JsonNull as error sentinel | infectious null returns | `raise ValueError(...)` + try/except |

Result: 374 lines → 152 lines, ~60% reduction. The natural form
compiles and runs first-try. **This is the strongest single piece of
evidence that M13-M17 collectively shipped a coherent language**, not
five disconnected features.

## The R4 worklist verification

M17's monomorphisation worklist is the most algorithmically complex
piece of M13-M17. R4 was specifically charter to hammer it. The
agent counted **8 distinct monomorphic instantiations** in the
final bytecode:

- `safe_get__i32`, `safe_get__f64`, `safe_get__str`,
  `safe_get__tuple_i32_f64`, `safe_get__class17` (Node) — 5 instantiations.
- `min_by__i32`, `enumerate__i32`, `first_or_default__i32` — 3 more.

Two of these (`safe_get__i32` and the dispatches inside `min_by`/
`first_or_default`) were discovered only TRANSITIVELY from inside other
generic bodies. Empirically confirms Pass 2.6 → Pass 3.5 fixed-point drain.
