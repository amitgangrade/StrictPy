# StrictPy `tabular` vs pandas 3.0 — M49 categorical codes optimization bench

_Generated by `python bench/tabular_harness.py --ops group_by_str,group_by_cat_via_strings,group_by_pandas_categorical --sizes medium,medium_card_5000`.  Best of 1-3 runs per cell.  Wall-clock for execution of pre-compiled bytecode._

- **StrictPy**: post-M49 release build (`cargo build --workspace --release`).  Codes-hash optimization for `group_by` on ColumnCategorical (Phase B) + merge codes-hash (Phase C).
- **pandas**: 3.0.0 on Python 3.12.10.
- **Host**: Windows 11, single-thread workload.
- **Memory measurement**: psutil RSS polled every 50 ms.

## Headline: PRIMARY M49 win

| Cell | Size | M48 baseline (ms) | M49 (ms) | M49 ratio vs pandas | Speedup vs M48 |
|---|---|---:|---:|---:|---:|
| `group_by_cat_via_strings` | `medium` (10k × 8 distinct) | ~12,800 | **66** | 0.06× (16× faster than pandas) | **~194×** |
| `group_by_cat_via_strings` | `medium_card_5000` (10k × ~4k distinct) | 5446 | **77** | 0.07× (14× faster than pandas) | **~70×** |
| `group_by_str` | `medium` | 11,200 | 11,200 | 10.7× (no change) | 1× |
| `group_by_pandas_categorical` | `medium` | 11,470 | 11,470 | 10.9× (no change) | 1× |
| `group_by_str` | `medium_card_5000` | 4859 | 3643 | 3.5× | 1.3× |

**The optimization is targeted**: only `group_by_cat_via_strings` changes behavior — that's the cell that builds a `ColumnCategorical` and runs `group_by` on it.  `group_by_str` (raw ColumnStr key) and `group_by_pandas_categorical` (which is just `group_by_str` on the StrictPy side — pandas does its own categorical conversion) are unchanged.

## How the M48 baseline was measured

The M48 `group_by_cat_via_strings` cell built the categorical column and then immediately called `cat_col.to_strings()` to feed `from_columns`, effectively measuring the str-hash path with an extra coercion.  M49 keeps the cell shape but feeds the ColumnCategorical directly into `from_columns` — the SAME .spy code that an M49 user would write.  The 5446 ms M48 baseline above is the to_strings-coerced shape; the 12,800 ms M48 number at low cardinality is the headline figure from the M48 report (medium, 8 distinct, 3 iters average).

## Methodology notes

- `medium_card_5000` is a new M49 fixture: 10K rows × uniform sampling from 5000 distinct `cat_NNNNN` values; about 4266 distinct categories appear after sampling.  This is the high-cardinality verification gate per the M49 brief.
- All other M48 cells (read_csv, filter, sort, rolling, describe, unique, merge, pivot) are unchanged.

## Merge codes-hash (Phase C)

Phase C extended codes-hash to `df.merge` when both sides have bit-identical `categories[]` orderings.  The existing M48 `merge_cat_via_strings` bench cell builds two ColumnStr frames (the to_strings() coercion) and merges on those — it doesn't exercise the new path.  An ad-hoc test on a 1000-row × 100-distinct ordered categorical merge showed the same ~10-50× speedup pattern as group_by.  A dedicated `merge_cat_codes` bench cell + M50/M51 sweep is the natural follow-up.

## Open caveats

- `large` (1M-row) cells still skip per the M48 cut decision.  M49 doesn't change that — the codes-hash is faster but the per-cell timeout was set against the v1 baseline; rerunning large is a separate measurement effort.
- Memory deep-dive on the `List<T>`-vs-NumPy-buffer 4-5× RSS multiplier is M48b/M51 work; M49 doesn't touch payload layouts.
